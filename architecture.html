How it is built

Architecture

Five websites, one API, one database. Everything a visitor downloads is a plain file from S3. Only API calls reach the server.

Five websites, each on its own address

storeease.inHomepageeveryonestoreease-global

Staff log in on dashboard. and are handed over to their store's address (see Keeping stores apart). One wildcard DNS record, *.storeease.in, covers every store, so a new signup needs no DNS work.

On AWS

Region Mumbai (ap-south-1). The certificate for CloudFront lives in N. Virginia, as AWS requires.

Why every app calls the API on its own address

This one rule explains a lot of the design.

The API finds the store from the addressA request to priya.storeease.in/api/… is about Priya's store
→
So each app calls /api on its own hostNo app ever sends a store id
→
BonusNo cross-site (CORS) setup, and login cookies stay locked to one address
How the address survives the tripCloudFront copies the visitor's address into a header (X-Storeease-Host) and adds a secret (X-Origin-Verify). nginx refuses anything without the secret and passes the address on to the API.

A second, private bucket for return photos

Customers' return photos are personal data, so they do not go in the uploads bucket.

No CloudFront, no public linkThe private uploads bucket has no CloudFront in front. The API checks who is asking, then hands the browser a link that works for 5 minutes (to upload a photo, or to look at one). The backend deletes a request's photos 90 days after it is final. Only the bucket's own address is added to the browser rules (CSP). Decision D-AWS8.

The stack

Backend

  • Python, FastAPI
  • SQLAlchemy (async), Alembic migrations
  • PostgreSQL 17 with Row-Level Security
  • Jinja2 emails, fpdf2 invoices

Frontend

  • React 19, Vite, TypeScript (strict)
  • React Router 7, TanStack Query 5
  • Tailwind 4, Radix UI, Recharts
  • Types generated from the API's OpenAPI

Homepage

  • Astro, static output
  • Plain CSS, ~9 KB of vanilla TS
  • GIFs fetched at build time, never by visitors

Infrastructure

  • Terraform (AWS provider 6)
  • S3, CloudFront, Route 53, ACM, ECR, SSM
  • One EC2 t3.micro with Docker Compose

Delivery

  • GitHub Actions, one checkbox per service
  • OIDC into AWS: no keys stored in GitHub

Third parties

  • Razorpay (subscriptions)
  • Let's Encrypt (server certificate)
  • GIPHY (homepage GIFs, build time)

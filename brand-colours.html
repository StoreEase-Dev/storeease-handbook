Every template in the shop's own colours.

Part of the template platform. Owners shouldn't need a designer's eye. They pick one brand colour, or just upload their logo, and StoreEase offers a few colour schemes that the template's designer has already shaped and that we have checked for readability.

Why "a colour picker for each colour" fails

Giving each colour in a template its own parameter (background, button, headings and so on) looks flexible, but it hands design work to people who didn't sign up for it.

Too many choices

Five independent colours can be combined in endless ways, and almost all of them clash. Most owners will leave the defaults, which then don't match their logo, or pick colours that fight each other.

Unreadable shops

Light yellow text on white or a dark logo on a dark header are easy mistakes to make. Shoppers can't read prices or find the button, and the shop loses orders without knowing why.

Templates lose their design

A template's designer made deliberate choices, such as a calm background or one strong button colour. Free colour fields can undo all of them, so a "premium" template no longer looks premium.

The idea in one line

The template decides where colour goes, the owner's brand decides which colour, and StoreEase makes sure the result is readable.

Five colour words, in plain language

You only need these to follow the rest of this page.

Contrast: can you read it?

How different two colours are in lightness. Dark text on a white page is very different, so it's easy to read. Light grey text on white is too similar, so it's hard to read. Contrast is measured as a number: 4.5 or more is the international minimum for normal text (the WCAG accessibility standard). Bigger is easier.

Shade: the same colour, lighter or darker

Every colour can be made lighter or darker while staying "the same colour", like paint with white or black mixed in. Below are shades of Priya's red, from dark to light; the ringed one is the red in her logo. The very light shades are good for backgrounds, the dark ones for text.

darkerlighter

Brand colour

The main colour of the shop's logo, like Priya's red. It's the colour shoppers remember. StoreEase finds it in the logo automatically, and the owner can change it.

Colour scheme

The full set of colours one shop uses: one for the page, one for the cards, one for the text, one for the buttons, one for the header. A good scheme has one strong colour (the brand) and calm colours everywhere else.

Every colour on a shop page has a job

Look at any shop page and the colours do five jobs. Tap a job to see where it is. Every template uses the same five jobs, which is why a colour scheme made for one template works in all of them.

Recipes: the designer decides which job gets which colour

A template's designer doesn't pick fixed colours. They write 2–4 recipes: short instructions such as "page white, buttons in the brand colour, header white". StoreEase fills in each shop's brand colour. So the designer keeps control of the look, and every shop still gets its own colours.

For developers: how a recipe is written in template.json 
"colours": {
  "recipes": [
    { "id": "clean", "name": "Clean white",
      "bg": "neutral 99", "surface": "neutral 96",
      "text": "neutral 20", "accent": "brand", "head": "bg" },
    { "id": "tint", "name": "Soft brand tint",
      "bg": "brand 97 soft", "surface": "brand 93 soft",
      "text": "brand 22 soft", "accent": "brand", "head": "brand 92 soft" },
    { "id": "bold", "name": "Bold header",
      "bg": "neutral 99", "accent": "brand", "head": "accent" }
  ],
  "default": "clean"
}

brand = the brand colour, nudged only as far as readability needs · brand 97 soft = the same hue at lightness 97/100 with little colour (a tint) · neutral = a grey with a faint hint of the brand hue · head: accent = header in the brand colour. The /parameterize-template skill proposes recipes from the design.

What StoreEase does, step by step

All of this happens in a split second in the owner's editor. Nobody has to know any colour theory.

1

Find the logo's colours

It looks at the logo's pixels, ignores the background, and groups similar colours. The biggest colourful one becomes the brand colour. Black, white and grey are ignored as brand colours (they're used only to check the logo stays visible).

2

Make lighter and darker shades

For each brand colour it makes a ladder of shades, from almost black to almost white. Recipes then pick from the ladder: "a very light shade for the page", "the logo's own shade for buttons".

3

Fill in every recipe

Each recipe of the chosen template is filled with each brand colour. Two brand colours × three recipes = six possible schemes.

4

Check everything can be read, and fix it if not

Every piece of text is checked against the colour behind it (contrast, 4.5 or more). If a button is too pale to read, StoreEase doesn't give up: it picks the nearest darker shade of the same colour. Only if nothing works is the scheme thrown away.

5

Show the best 4–6

Schemes using the logo's main colour come first, then the ones that needed the smallest change. A scheme where the logo would blend into the header goes lower and is marked. The owner taps one, as in Try it.

For developers: the libraries and rules

Extract: the logo is drawn to ~64×64 pixels; transparent pixels and the background (the most common border colour) are skipped; colours are grouped by OKLab distance and ranked by area. The dashboard's logoColours.ts already does a basic version; it moves to the SDK.

Shades: Material Color Utilities (Google, open source, TypeScript, Apache 2.0), the engine behind Android's colours from the wallpaper. It builds a tonal palette (tone 0–100) in the HCT colour space, where a tone is equally light for every hue, so the contrast rules behave the same for red and for yellow.

Fix: a failing button colour moves along its tonal palette to the nearest tone that passes. Rank: logo share, then distance between the button colour and the brand colour; penalties for a fading logo and a big shade change; at most two cards per recipe and per colour.

Where: in the browser (instant); the backend recomputes contrast on publish and refuses an unreadable scheme. This page's demo uses a simplified version (OKLCH) of the same idea.

Logos with no colourA black, white or grey logo has no colour to borrow. Then the cards use calm grey recipes plus three safe colours (blue, teal and amber), and the owner can pick their own.

Catching bad templates before approval

Before a new template version can go live, an automatic check tries each of its recipes with 12 very different brand colours (red, yellow, navy, pink…). The admin sees the result next to the version, so a template that only looks good in blue is caught before any customer gets it. This is the check for the template chosen in Try it: each small tile is "header + page + button".

✓ works as is~ works after a big shade change: the shop may not look like its brand✗ can't be made readable: blocks approval
For developers: the same check on the command line
$ npm run check -- clean-store ✓ colours: 3 recipes × 12 sample brands, all readable ~ "Bold header" + yellow: button shade changed a lot (tone 80 → 45) ✓ report attached to the version for the admin

Proposal: a recipe that can't be made readable for some colour blocks approval; "~" results are warnings the admin can accept. Whether the logo stays visible depends on the real logo, so that check happens in the owner's editor.

How others handle it

Nobody in this space leaves owners alone with five free colour pickers. The common answers are schemes instead of single colours, and generating them from one seed colour.

ProductWhat they doWhat we take from it
ShopifyThemes define colour schemes: sets of background, text and button colours. Each section of the shop picks a scheme. Merchants edit the schemes by hand; nothing comes from the logo and contrast is up to them.Schemes, not loose colours. We add the logo and the checks.
SquarespaceThe owner sets a small site palette of about five colours. Squarespace derives light and dark "colour themes" from it, and sections choose a theme, never an individual colour.A few inputs, many derived looks; sections stay consistent.
Android (Material You)One seed colour, taken from the wallpaper, generates a complete scheme of tonal palettes with contrast built in. The engine is open source.The generator itself: Material Color Utilities (TypeScript, Apache 2.0).
Canva, Coolors, Adobe ColorBrand kits store brand colours; generators suggest palettes from a photo or from colour-harmony rules (complementary, analogous colours).Brand colours saved once and reused everywhere; palette from an image.

Running it

Run it locally

Everything runs on one Windows laptop: the API and database, a test inbox, and all five websites behind one "gateway" that plays CloudFront's part.

Before the first run

Tools

  • Node 22.12+ and npm
  • Python + the backend's .venv
  • PostgreSQL 17 running
  • Mailpit (winget install axllent.mailpit)

Backend once

  • Create the 3 database roles (bootstrap/roles.sql)
  • Copy .env.example → .env
  • alembic upgrade head

Frontend once

  • npm ci
  • Copy .env.example → .env.local
  • Homepage: npm install

Three terminals

1

Backend

cd storeease-backend
$env:STOREFRONT_BASE_DOMAIN='localhost'
$env:DASHBOARD_HOST='dashboard.localhost:8080'
.\.venv\Scripts\uvicorn.exe app.main:app --port 8000

API docs: http://127.0.0.1:8000/docs

2

Frontend

cd storeease-frontend
npm run dev

All four apps + the gateway on 8080.

3

Homepage

cd storeease-global
npm run dev:gateway

Astro on 5104, shown through the gateway.

How the gateway routes

Chrome, Edge and Firefox send *.localhost to your own machine, so no hosts-file edits.

OpenYou get
http://localhost:8080Homepage. Sign up / Login go to the account app
http://dashboard.localhost:8080/loginLogin and signup
http://demo-store.localhost:8080The demo store's shop
http://demo-store.localhost:8080/dashboardIts dashboard
http://admin.localhost:8080Admin portal
http://127.0.0.1:8025Mailpit: login codes, invites, resets

Test data

A big demo store

psql "<storeease_admin url>" -f scripts/demo-data/seed_demo_store.sql

Owner owner.demo-store@example.com / demo-password-123. Then run ANALYZE as the migrator, or some pages are slow until autovacuum catches up.

A whole platform

psql "<storeease_admin url>" -v stores=40 -f scripts/demo-data/seed_platform.sql

Stores seed-001… with 12 months of trials, payments, churn and orders, for the admin charts.

A platform admin

python -m app.cli.admin create --email ops@example.com --name Ops

Switch on the inventory add-on

python -m app.cli.admin addon activate --tenant demo-store --addon inventory_management

When something's off

Every API call fails with 500

Postgres is probably down: /healthz queries the database.

"Store not found" locally

Set STOREFRONT_BASE_DOMAIN=localhost for the backend.

A staff member sees nothing

They need a role. No role = no access, on purpose.

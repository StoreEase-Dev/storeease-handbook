How it is built

The apps

Four React apps share one code repository (storeease-frontend), plus the Astro homepage in its own. Every app is plain files: nothing renders on a server.

How the code is arranged

Apps use shared packages; dependencies only point downwards. Storefront templates never use the dashboard's design system, so shops look nothing like the back office.

The dashboard

Calm version of the homepage look: ink sidebar, frost page, white cards, green buttons with ink text.

Three storefront templates

Completely different designs, not recolours. A visitor downloads the shop engine plus only the one template the store uses. The owner's own colours, font and logo sit on top.

minimal

Clean Store

Bright, lots of white space, restrained motion. Suits small catalogues.

dark

Dark Futuristic

Dark surfaces, high contrast, accent glow, spotlight sections.

Mobile Lighthouse: performance 95-98, accessibility 100 on every template. The designs are placeholders the owner may replace; swapping one is a new package plus one line.

Rules every page follows

Four states

Every data view handles loading, empty, error (with retry) and data, plus every error code the API can send.

Types from the API

Never hand-write an API type. After a backend change: npm run api:types.

Money and dates

Paise in, paise out; formatted only on screen. Every date range is an India-time (IST) day.

Never shown to shoppers

Exact stock counts. Only "in stock", and "only N left" on a line that asks for too many.

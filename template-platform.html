From three templates to a template platform.

Our developers ship templates from one repo. The admin publishes them as Regular, Premium or Private to one shop. Owners pick one from a gallery, choose its version, customise it with a live preview, and publish when they're happy. A shop never changes until its owner says so.

Versions: frozen once published, updated only by the owner

A developer can release a new version at any time. Shops stay on the version they chose until the owner updates. Try it: release a version, publish it as the admin, then update the shop as its owner.

The rules

  • Every release gets a new number in template.json. The pipeline refuses to overwrite a number that exists.
  • A release shows to owners only after the admin publishes it, with release notes.
  • Owners pick the version when they choose a template (the latest by default) and see an "Update available" badge later.
  • No automatic updates, ever. The owner opens the update in the editor, reviews it, and publishes.

What an update keeps

  • Every setting that still exists keeps the owner's value.
  • New settings start from their defaults and are highlighted.
  • Settings the new version dropped are listed in Review before anything changes.
  • The owner can go back to the previous version while it isn't retired. A retired version disappears for new shops; shops already on it keep it.

Who sees which template

Each template is Public (Regular or Premium) or Private. A Private template is one we build for a particular shop: in its setup the admin ticks Private and picks the shop (or shops) it's for. Only they see it, and like Premium templates it needs the ₹999 plan.

The developer skill

The templates repo ships a Claude Code skill that does the tedious part of making a template: it turns hard-coded content into parameters and checks the template only uses what our engine offers.

What it does

  • Finds what should be editable: texts, images, colours and fonts written into the code. It proposes params.json with sections, labels, limits and defaults.
  • Rewrites the code to read those values through the SDK (useParam, ParamImage, colour variables). Store name, logo and colours default to the shop's brand.
  • Checks capabilities: every data read, form and link is compared with what the engine provides (store details, categories, products, search, cart, login, checkout, account, orders, returns, UPI payment). Anything else, like a wishlist, blog posts or posting reviews, is flagged before review.
  • Runs the same checks as the pipeline locally, so a release doesn't fail on things the developer could have caught.

Build plan

Three waves of at most three agents each, then a wrap-up. Open a wave for what it delivers.

Before Prepare
  • You create the empty private repo storeease-templates.
  • I write the round-4 agent kit, and create the issues and board cards. Backend #111 (plan tiers and template gating) becomes part of this work.
  • The partners answer the open questions below.
Wave 1 Backend, SDK and pipeline, infra
  • Backend: tables template_builds (every uploaded version), templates (the catalogue: details, tier, Public or Private, shops for Private, status) and store_designs (per shop and template: chosen version, draft values, published values, history). Owner, admin and pipeline APIs; plan and Private checks; the downgrade rule in the billing sweep.
  • SDK and templates repo: the SDK package (useParam, data hooks, engine pages), the parameter-file format, a starter template, the Claude Code skill, and the release pipeline (validate, build, render test, speed check, upload a frozen version, register it).
  • Infra: a templates/ path on the CDN with permanent caching, the storefront's browser rules allowing that host, and an upload role only the templates repo can use.
Wave 2 Owner screens, admin screens, converting today's templates
  • Dashboard, Templates: gallery with tiers, "Made for you" and filters; version picker and "Update available"; the editor with the Desktop / Mobile switch; Review with what changed; Publish, discard and go back. Template choice leaves Store settings.
  • Admin portal, Templates: new template from an unused build, defaults and preview, details, screenshots, Regular / Premium / Private with shop picker, publish and retire per version, usage counts.
  • Storefront: loads the chosen version from the CDN; Clean Store, Modern D2C and Dark Futuristic move into the repo as version 1.0, and every live shop keeps its exact look.
Wave 3 Wrap-up
  • Docs, the handbook, and a tester-guide chapter for templates and versions.
  • End-to-end tests: build to admin publish to owner publish to shopper; an update; a downgrade; a Private template.
